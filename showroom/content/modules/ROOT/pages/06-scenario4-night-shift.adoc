= 06. Scenario 4: The night shift
:navtitle: 06. Scenario 4: The night shift
:toc: macro
:toclevels: 2

toc::[]

An outsourced night-shift contractor's account (or its leaked token) is scripted at 3 a.m. to loop long requests and drain the model budget. Unsecured, the shared key burns all night. Secured, the off-topic junk is refused for free, only that account is throttled, an alert names the user, and the operator has two one-click responses.

The script `scripts/night-shift.sh` plays the scripted account. It logs in as `nina.contractor` (Nina Patel, a contractor with read-only claim tools), sends two off-topic requests, then loops long on-topic requests, printing the HTTP status, the caller and the token spend of each. It stops at the first usage-limit response and has a hard ceiling, so a stray run cannot drain the model key.

[NOTE]
.Know: budgets and alerts with a name
====
An agent on a shared key is an open invoice: anyone who can reach the chat can spend the budget, and nobody can say who did. On the platform, spend is attributed to a user, so the right account is throttled, everyone else keeps working, and the alert says who.
====

== Before you start

This scenario runs on its own, in any order with the others.

* Personas: `nina.contractor` (the night-shift contractor, played by the script) and `rebecca`; passwords equal the user names.
* State: `nina.contractor` is enabled in Keycloak, the kill switch is off, and her token budget is full. If an earlier run used any of them, undo it as in *Reset after this scenario* below.

== Show: unsecured

. In the *Terminal* tab, run the night shift against the unsecured portal:
+
[source,bash,role=execute,subs=attributes]
----
scripts/night-shift.sh 40 portal-free.{domain}
----

. Watch the script output.
+
What you should see: every request is answered; there is no per-user limit on the shared key. Left running all night, the budget is gone by morning and the assistant answers the claims staff with "budget exhausted".
+
Then look for this traffic on the platform: there is none to find. The unsecured portal calls the model provider directly with a key from a Secret, so no subscription, budget, dashboard or alert covers it.
+
The point: denial of wallet, and nobody was watching.

== Show: secured

. In the *Terminal* tab, give `nina.contractor` a full token budget again:
+
[source,bash,role=execute]
----
scripts/reset.sh
----

. Run the night shift against the secured portal (the default target):
+
[source,bash,role=execute]
----
scripts/night-shift.sh 40
----

. Watch the script output.
+
What you should see:
+
* the off-topic requests get a polite refusal from the topic guardrail at *0 tokens*;
* the on-topic loop keeps hammering, and the per-user spend climbs;
* after the per-user limit, the response reads "you have reached your usage limit (429)" and the script stops.

. Select the *Portal secured* tab, sign in as `nina.contractor`, open any claim and ask a question.
+
What you should see: the chat answers with the usage-limit message "You have reached your usage limit (429). Please try again later." The account, not the portal, is out of budget.

. In the same *Portal secured* tab, sign out, log in as `rebecca`, open any claim and ask a question.
+
What you should see: rebecca keeps working normally. Only `nina.contractor` is throttled.

== Show: on the platform

The governance beat for the night: who spent the budget, through which agent, what stopped them, and who was told. Three screens, then the operator acts.

. Select the *OpenShift Console* tab, *Observe*, *Dashboards*, project `openshift-operators`, dashboard *Parasol Assistant Token Spend*. Set *User* to `nina.contractor` if the other personas crowd the view.
+
What you should see, in the row *Token spend*:
+
* *Token spend per user and agent* climbing as `nina.contractor via parasol-claims-agent` past the red 5000 tokens/min line, while `rebecca via parasol-claims-agent` stays low;
* *Tokens by user and agent* with `nina.contractor`, `parasol-claims-agent`, `secured` on top;
* *ParasolAssistantTokenSpendHigh: alert state* stepping to `firing nina.contractor via parasol-claims-agent`.
+

== Show: the operator's response

Pick one. Reach for the precise control first.

=== Option A: disable the user

. Select the *Keycloak* tab. In realm `parasol`, open *Users*, then `nina.contractor`, and switch *Enabled* off. Save.

. In the *Terminal* tab, run the night shift once more:
+
[source,bash,role=execute]
----
scripts/night-shift.sh 3
----
+
What you should see: the script cannot log in as `nina.contractor`. Everyone else keeps working.

. Re-enable `nina.contractor` in the *Keycloak* tab after the demo.

=== Option B: the kill switch

The kill switch is a kustomize component already in Git (`gitops/envs/secured/kill-switch`). You switch it on in the cluster, on the Argo CD Application, not with a Git commit.

. Select the *Argo CD* tab and open application `env-secured`. Click *Details* in the top bar, select the *Manifest* tab and click *Edit*.

. Under `spec.source.kustomize`, at the same indentation as `patches:`, add one line, then click *Save*:
+
[source,yaml]
----
components: [kill-switch]
----
+
The same change from the *Terminal* tab:
+
[source,bash,role=execute]
----
oc patch application env-secured -n openshift-gitops --type merge -p '{"spec":{"source":{"kustomize":{"components":["kill-switch"]}}}}'
----
+
What you should see: Argo CD syncs `env-secured` on its own; the component replaces the portal's network egress.

. Select the *Portal secured* tab and ask the assistant anything.
+
What you should see: after about 50 seconds the assistant reports it is offline. In the *OpenShift Console* tab, the pods in project `parasol-secured` are still *Running*: they simply reach nothing.

. Switch it off to bring the assistant back: in *Details* > *Manifest* > *Edit*, delete the `components` line and click *Save*. From the *Terminal* tab:
+
[source,bash,role=execute]
----
oc patch application env-secured -n openshift-gitops --type merge -p '{"spec":{"source":{"kustomize":{"components":null}}}}'
----

The morning report is two screens you already have open: the alert and the dashboard.

== Reset after this scenario

. Refill the per-user token budgets (and put the claims back):
+
[source,bash,role=execute]
----
scripts/reset.sh
----

. If you used Option A, re-enable `nina.contractor` in the *Keycloak* tab. If you used Option B, switch the kill switch off:
+
[source,bash,role=execute]
----
oc patch application env-secured -n openshift-gitops --type merge -p '{"spec":{"source":{"kustomize":{"components":null}}}}'
----

The `ParasolAssistantTokenSpendHigh` alert resolves on its own 10 minutes after the spend stops.
