= 07. Scenario 5: The evaluation gate
:navtitle: 07. Scenario 5: The evaluation gate
:toc: macro
:toclevels: 2

toc::[]

A developer proposes a shorter system prompt for the assistant, the *candidate: shortened prompt*. Before the change can reach production, the platform evaluates it against a fixed golden set. The regression is caught and promotion is blocked. This scenario runs in the consoles, not in a portal.

[NOTE]
.Know: quality is enforced, not hoped for
====
A prompt change is a code change: it can silently remove a safety behavior. A version that fails the evaluation cannot be promoted, and every score is tied to the exact prompt and model version it measured.
====

== Before you start

This scenario runs on its own, in any order with the others. It only reads what the installation recorded:

* the EvalHub run, the golden-set evaluation runs and both registered prompt versions (`scripts/seed-demo.sh`, run by the installation);
* the two release runs `parasol-portal-release-production` and `parasol-portal-release-candidate-shortened` in project `parasol-build`. If one is missing, start it again in the *Terminal* tab (about 20 to 30 minutes):
+
[source,bash,role=execute]
----
scripts/pipeline-runs.sh
----

== Show: the evaluation run

. Select the *OpenShift AI* tab, open *Develop & train*, then *Evaluations* (Technology Preview), and select project `parasol-eval`.
+
What you should see: the run `parasol-agent-model-ifeval` in state *Completed*. EvalHub, the TrustyAI evaluation service running in the project, evaluated the agent's model (`qwen3-14b` on the external MaaS endpoint) with LM Evaluation Harness on the IFEval instruction-following benchmark. Open the run to show its metrics (for example `inst_level_strict_acc` 0.375 and `prompt_level_strict_acc` 0.2) and its result against the default pass threshold of 0.5.
+
Say: this is a five-prompt smoke run of a generic benchmark, so the number is not the point. The point is that evaluation is a platform service with a recorded result per model. Whether this assistant is safe to ship is decided by its own golden set, next.
+

== Show: the golden set, production prompt against the candidate

. Select the *MLflow* tab, open experiment `parasol-agent-eval`, then *Evaluation runs*.
+
What you should see: the golden set `parasol-golden-20` scored on every run, each case judged by `gpt-oss-120b`. The *production prompt* (runs `production-prompt`) scores *20/20, PASS*; the *candidate: shortened prompt* (runs `candidate-shortened-prompt`) scores *17/20, BLOCK*, failing the injection-document, role-authorization and other-claimant cases.

== Show: the gate

. Select the *OpenShift Console* tab and open *Pipelines*, project `parasol-build`, then *Pipeline runs*. Direct link: link:{console_url}/k8s/ns/parasol-build/tekton.dev~v1~PipelineRun[parasol-build pipeline runs,window=_blank].
+
What you should see: two release runs of the same pipeline. In `parasol-portal-release-production` (the production prompt) `agent-eval` passed with `EVAL_SCORE 1.00` and `promote` ran. In `parasol-portal-release-candidate-shortened` (the candidate: shortened prompt) `agent-eval` failed with `EVAL_SCORE 0.85` and `promote` is *skipped*: the candidate was built, scanned and even signed, but it was never promoted, so nothing reached production.
+
// SCREENSHOT: sc-pipeline-v2-blocked.png — Console, Pipelines, parasol-build, run parasol-portal-release-candidate-shortened: agent-eval failed (EVAL_SCORE 0.85), promote skipped (recapture: old run name)
image::sc-pipeline-v2-blocked.png["The candidate-shortened release run: every stage ran, and promote was skipped by the evaluation gate"]

. Select the *OpenShift AI* tab and open *Model registry*, then `parasol-claims-assistant`, then *Versions*.
+
What you should see: version `production` with gate `passed` and 20/20, and version `candidate-shortened` with gate `failed` and 17/20: each evaluation score tied to the agent version the pipeline would promote.

== Show: the gated prompt at runtime

The link back from the gate to production: every live chat turn names the prompt it ran with.

. Select the *MLflow* tab, workspace `parasol-secured`, experiment `parasol-portal-chat`, *Traces*. Open any recent chat trace (for example the CLM-1004 turn from Scenario 2), or search with `tags.agent = 'parasol-claims-agent'`.
+
What you should see: the trace tag `prompt` `parasol-claims-assistant-system-prompt@production`, next to `agent` `parasol-claims-agent` and `model` `qwen3-14b`; on the root span the same value as `gen_ai.prompt.ref`. It is the alias the production release run was gated on (`prompt-ref` on the `env-secured` Application, xref:08-supply-chain.adoc[08. Supply chain]); the shortened candidate never appears here, because it was never promoted.
