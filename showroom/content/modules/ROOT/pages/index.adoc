= AI Agents: From localhost to Production

Anyone can stand up an AI agent on a laptop in an afternoon. Running that same agent in production, where real people use it, feed it real documents and try to abuse it, is where the hard problems live. This guide is the presenter's script for a live demonstration of that gap, and of how an OpenShift-based platform closes it.

== The premise: the Parasol claims assistant

Parasol Insurance runs a claims portal (Quarkus and React/PatternFly, Keycloak login). Beside each claim sits a chat assistant. It is not a chatbot: it is a tool-using agent that calls MCP tools to read claims and policy documents and to approve payouts.

An agent that can move money is an agent worth abusing.

== One image, two portals

The same portal image runs twice on one cluster, over separate, identically seeded claims databases:

* *Portal unsecured* (`portal-free`): the laptop setup lifted into a namespace. Nothing sits between the agent and its tools, and nothing between the agent and the model but an API key in a Secret.
* *Portal secured* (`portal`): the same image behind a layered sandbox: namespace isolation, Keycloak identity on every tool call, per-identity tool authorization at an MCP gateway, content guardrails, Models-as-a-Service governance with per-user token budgets, tracing and token metrics, a GitOps kill switch on the Argo CD Application, and a signed-image supply chain with admission control.

You demo the *same claim* with the *same request* on each portal. The only variable is the platform.

== The four scenarios

. *The colleague.* A claims adjuster asks the assistant to approve a payout the adjuster has no authority to approve.
. *The customer's document.* An uploaded repair estimate is inflated to AED 84,000 and carries a hidden note addressed to the assistant.
. *The night shift.* An outsourced night-shift contractor's account (or its leaked token) is scripted at 3 a.m. to drain the token budget.
. *The evaluation gate.* A developer simplifies the system prompt; the platform evaluates it against a golden set and blocks the regression.

Unsecured, the first three cause harm. Secured, a *different* layer stops each, and the platform consoles show why.

[NOTE]
.The five messages to land
====
. Identity on every tool call.
. A document is data, not a command.
. Read, propose, act: a person with the right role makes every write.
. Budgets and alerts with a name.
. The sandbox has a front door: identity-bound access, not a wall.
====
