The agent reached production the same way any workload should: a pipeline that signs what it builds, an admission control that refuses what is not signed, and an evaluation that blocks a bad version before it ships. These controls live in MLflow and the pipeline for the parasol-secured workspace.

== Signing in the build

The build pipeline signs the three images that make up the agent:

* `parasol-portal`
* `claims-db`
* `policy-docs`

Signing is keyless. There is no long-lived signing key to store or leak. The signature is bound to the build identity and recorded in a transparency log.

. Open the *OpenShift Console* tab and show a completed pipeline run.
+
What you should see: the signing step succeeding for all three images.

== Evaluation gates promotion

The agent is evaluated against a golden set of 20 cases before it can be promoted. Each case is scored by a deterministic scorer and a judge scorer. A pipeline gate blocks promotion when the score falls below 19 out of 20.

. Open the *MLflow* tab in the parasol-secured workspace and show the evaluation run.

== The prompt registry and a failed version

The system prompt is versioned in a registry. Version 1 passes the golden set. A simplified version 2 failed 3 of 20 cases. The registry holds both, side by side, so the failure is visible and the promotion gate has something to compare.
