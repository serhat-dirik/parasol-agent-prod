Ten minutes before the audience arrives: confirm the platform is healthy, sign in to the consoles, and reset the demo data.

[NOTE]
.Presenter note
====
Do this page before the session, not in front of the audience. Everything after it assumes the consoles are signed in and the claims data is fresh.
====

== Check the platform

. Select the *Terminal* tab.
+
What you should see: a shell prompt in the `parasol-agent-prod` repository, with `oc` signed in as the Showroom's terminal identity.

. Confirm every Argo CD application is Synced and Healthy and both portals are up:
+
[source,bash,role=execute]
----
scripts/status.sh
----

. Sign in to Argo CD once in a normal browser tab: open link:{argocd_url}[Argo CD,window=_blank], click *Log in via OpenShift*, sign in and click *Allow*. Then select the *Argo CD* tab and reload it.
+
Argo CD keeps its own session. Its *Log in via OpenShift* button goes to the OpenShift sign-in page, which refuses to open inside a tab ("refused to connect"), so this one sign-in must happen outside the Showroom.
+
What you should see: every component Synced and Healthy. Argo CD is the GitOps source of truth for the whole demo.

== Sign in to the consoles

This Showroom itself sits behind the OpenShift sign-in, so you signed in to OpenShift when you opened it. The OpenShift console, OpenShift AI, MLflow and Argo CD tabs use the same OpenShift sign-in and reuse that session. The OpenShift sign-in page itself (a passthrough route) cannot be shown inside a tab.

. Select the *OpenShift Console*, *OpenShift AI*, *MLflow* and *Argo CD* tabs in turn.
+
What you should see: each one opens signed in. If a tab shows a sign-in button, a blank page or "refused to connect", do not sign in inside the tab: open that console in a normal browser tab (link:{console_url}[OpenShift console,window=_blank], link:{rhoai_url}[OpenShift AI,window=_blank], link:{mlflow_url}[MLflow,window=_blank], link:{argocd_url}[Argo CD,window=_blank]), sign in there once, then reload the Showroom tab. It is a one-time step per browser session; do it before you present.

. Open the Keycloak admin console in a *private (incognito) window*, link:{keycloak_url}/admin/parasol/console/[Keycloak admin,window=_blank], and sign in with username `admin`, password `admin`. This account administers only the demo's realm `parasol` (users, groups, clients, events); it has no rights anywhere else in Keycloak. Keep that window open for the Keycloak steps of every showcase.
+
What you should see: realm `parasol`.
+
[IMPORTANT]
====
The portals and the Keycloak admin console share *one sign-in per browser*, because they are all in realm `parasol`. Signed in as `admin` in the same browser, the portals would open as "Parasol Admin" instead of asking for a persona; signed in as a persona, the Keycloak tab would open as that persona, who has no admin rights; and logging out in one logs out the other. The private window keeps the two apart: personas in the Showroom portal tabs, `admin` in the private window. Do not sign in inside the Showroom *Keycloak* tab.
====

== Consoles, dashboards and logs: where to look

Every secured beat is visible on the platform, not only in the portal chat.

* *Argo CD* tab: every component Synced and Healthy. `scripts/status.sh` summarizes it.
* *OpenShift AI* tab: *Settings*, *MaaS governance* (the subscriptions and their token limits), *Gen AI studio* (playground, API keys, prompts), *AI hub* (*Models* > *Registry*: the MaaS models and the evaluated agent versions; *MCP servers* and *Agents* catalogs) and *Evaluations* (TrustyAI). Module 01 lists the click paths.
* *MLflow* tab: chat traces (workspace `parasol-secured`, experiment `parasol-portal-chat`; each secured chat turn links to its own trace), and the `parasol-agent-eval` golden-set runs.
* *OpenShift Console* tab:
** Observe, Dashboards (Perses), project `parasol-secured`, dashboard *Parasol Assistant Token Spend*: token spend per user and agent, the spend alert, tool calls, gateway rejections by reason and guardrail hits, filterable by user and agent;
** Observe, Alerting: the alert `ParasolAssistantTokenSpendHigh`;
** Observe, Metrics: `parasol_tool_calls_total` and token spend;
** Observe, Traces: the Tempo trace of each chat turn;
** Networking, Gateways: the MCP and MaaS gateways and their AuthPolicies (Enforced).
* *Keycloak* (admin console in a private window, see above): realm `parasol`, users, groups, events and the `tool:*` roles.
* *Terminal* tab, live logs to confirm a beat at the component level:
** guardrails on the model path (the user's message, the answer):
+
[source,bash,role=execute]
----
oc logs -n parasol-secured deploy/guardrails-proxy --tail=50
----
** guardrails on tool results (a document refused at the MCP gateway, with the rule that fired):
+
[source,bash,role=execute]
----
oc logs -n mcp-system deploy/mcp-gateway --since=1h | grep 'guardrails blocked'
----
** gateway refusals, naming the person and the agent (`not via an approved agent: <user> azp=<client>`, `tool <tool> denied for <user> azp=<agent>`):
+
[source,bash,role=execute]
----
oc logs -n kuadrant-system deploy/authorino --tail=500 | grep -E 'approved agent|denied for'
----
** token-budget 429s (per MaaS subscription, that is per tier):
+
[source,bash,role=execute]
----
oc logs -n kuadrant-system deploy/limitador-limitador --tail=50
----

== Reset the demo data

. In the *Terminal* tab, reset both portals' claims and refill the token budgets:
+
[source,bash,role=execute]
----
scripts/reset.sh
----
+
What you should see: `parasol-free reset`, `parasol-secured reset` and `model allowance reset`.

. Select the *Portal unsecured* tab, then the *Portal secured* tab.
+
What you should see: the Parasol sign-in page on each.

The two portals have separate databases, so you do not reset when you switch between them within a showcase. The showcases tell you when a reset is needed.
