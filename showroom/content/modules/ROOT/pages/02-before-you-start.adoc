Ten minutes before the audience arrives: confirm the platform is healthy, sign in to the consoles, and reset the demo data.

[NOTE]
.Presenter note
====
Do this page before the session, not in front of the audience. Everything after it assumes the consoles are signed in and the claims data is fresh.
====

== Check the platform

. Select the *Terminal* tab.
+
What you should see: a shell prompt in the `parasol-agent-prod` repository, with `oc` signed in as the Showroom's terminal identity.

. Confirm every Argo CD application is Synced and Healthy and both portals are up:
+
[source,bash,role=execute]
----
scripts/status.sh
----

. Select the *Argo CD* tab and sign in.
+
What you should see: every component Synced and Healthy. Argo CD is the GitOps source of truth for the whole demo.

== Sign in to the consoles

This Showroom itself sits behind the OpenShift sign-in, so you signed in to OpenShift when you opened it. The OpenShift console, OpenShift AI, MLflow and Argo CD tabs use the same OpenShift sign-in and reuse that session. The OpenShift sign-in page itself (a passthrough route) cannot be shown inside a tab.

. Select the *OpenShift Console*, *OpenShift AI*, *MLflow* and *Argo CD* tabs in turn.
+
What you should see: each one opens signed in. If one still shows a sign-in button, click it once. If a tab stays blank, open link:{console_url}[the OpenShift console,window=_blank] in a normal browser tab, sign in there once, and reload the tab.

. Select the *Keycloak* tab and sign in to the administration console.
+
What you should see: realm `parasol`.

== Consoles, dashboards and logs: where to look

Every secured beat is visible on the platform, not only in the portal chat.

* *Argo CD* tab: every component Synced and Healthy. `scripts/status.sh` summarizes it.
* *OpenShift AI* tab: Models-as-a-Service (the two tiered models, `qwen3-14b` and `granite-guardian-3-1-8b`, with per-key usage), the GenAI Studio playground, and Model evaluation runs (TrustyAI LMEval).
* *MLflow* tab: chat traces (workspace `parasol-secured`, experiment `parasol-portal-chat`; each secured chat turn links to its own trace), and the `parasol-agent-eval` golden-set runs.
* *OpenShift Console* tab:
** Observe, Dashboards, project `openshift-operators`, dashboard *Parasol Assistant Token Spend*: token spend per user and agent, the spend alert, tool calls, gateway rejections by reason and guardrail hits, filterable by user and agent;
** Observe, Alerting: the alert `ParasolAssistantTokenSpendHigh`;
** Observe, Metrics: `parasol_tool_calls_total` and token spend;
** Observe, Traces: the Tempo trace of each chat turn;
** Networking, Gateways: the MCP and MaaS gateways and their AuthPolicies (Enforced).
* *Keycloak* tab: realm `parasol`, users, groups and the `tool:*` roles.
* *Terminal* tab, live logs to confirm a beat at the component level:
** guardrails flag or block:
+
[source,bash,role=execute]
----
oc logs -n parasol-secured deploy/guardrails-proxy --tail=50
----
** gateway refusals, naming the person and the agent (`not via an approved agent: <user> azp=<client>`, `tool <tool> denied for <user> azp=<agent>`):
+
[source,bash,role=execute]
----
oc logs -n kuadrant-system deploy/authorino --tail=500 | grep -E 'approved agent|denied for'
----
** per-user 429:
+
[source,bash,role=execute]
----
oc logs -n kuadrant-system deploy/limitador-limitador --tail=50
----

== Reset the demo data

. In the *Terminal* tab, reset both portals' claims and refill the per-user token budgets:
+
[source,bash,role=execute]
----
scripts/reset.sh
----
+
What you should see: `parasol-free reset`, `parasol-secured reset` and `model allowance reset`.

. Select the *Portal unsecured* tab, then the *Portal secured* tab.
+
What you should see: the Parasol sign-in page on each.

The two portals have separate databases, so you do not reset when you switch between them within a scenario. The scenarios tell you when a reset is needed.
