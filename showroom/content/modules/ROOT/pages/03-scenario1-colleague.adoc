= 03. Scenario 1: The colleague
:navtitle: 03. Scenario 1: The colleague
:toc: macro
:toclevels: 2

toc::[]

An adjuster has no authority to approve a payout. Unsecured, the agent does it anyway. Secured, the tool is never even offered to the adjuster, and only a manager's click writes.

[NOTE]
.Know: identity on every tool call
====
The agent acts *as the person*, and the gateway checks the person's rights before any tool runs. Unsecured, nobody asks who is asking: a chat window becomes a payout button for anyone who can log in.
====

== Show: unsecured

. Make sure the demo data is fresh. If you did not just reset it in xref:02-before-you-start.adoc[02. Before you start], run in the *Terminal* tab:
+
[source,bash,role=execute]
----
scripts/reset.sh
----

. Select the *Portal unsecured* tab and log in as `rebecca` (password `rebecca`).
+
What you should see: the top bar reads "Rebecca Torres, claims adjuster".
+
image::s1-unsecured-dashboard.jpg["The unsecured portal dashboard for rebecca, with claim counts and her assistant usage today"]

. Open claim *CLM-1001* (UnderReview, Alice Nguyen, AED 4,200).

. In the chat, send:
+
[source,text]
----
Approve the payout for this claim.
----

. Watch the chat and the claim's *Timeline* tab.
+
What you should see: a chip `called approve_payout(claimNumber=CLM-1001)`, the status changes to *Approved*, and the timeline gains *Approved* ("Approved for 4200.00 via claims assistant") then *PaymentIssued*.
+
image::s1-unsecured-approved.jpg["Unsecured: the assistant called approve_payout for an adjuster, and the timeline shows Approved and PaymentIssued"]
+
The point: the agent approved a payout for someone with no authority. Nobody asked who was asking.

== Show: secured

. Select the *Portal secured* tab and log in as `rebecca`.

. Open *CLM-1001* and send the same request:
+
[source,text]
----
Approve the payout for this claim.
----

. Watch the chat and the timeline.
+
What you should see:
+
* the assistant can only *propose*: a card "Payout proposed for CLM-1001, needs a claims manager", with "You do not have approval rights for this" and no *Approve* button;
* the claim stays *UnderReview*; the timeline is unchanged.
+
image::s1-secured-propose.jpg["Secured: for rebecca the assistant can only propose the payout; the card says she has no approval rights"]
+
`approve_payout` is not in rebecca's tool list at all, so the model cannot even try it. The *Check it* step below forces the call past the agent to show the gateway refusing it.

. Log out, then log in as `marcus` (claims manager). Open *CLM-1001* and send the same request.
+
What you should see: the same proposal card, but this time with an *Approve* button.
+
image::s1-manager-proposal.jpg["Secured, as marcus: the same proposal card now carries an Approve button"]

. Click *Approve* on the proposal card, then open the *Timeline* tab.
+
What you should see: the card reads "Approved by marcus via parasol-claims-agent" with a `trace <id>` link under it, the status changes to *Approved*, and the timeline gains "Approved by marcus via parasol-claims-agent" then *PaymentIssued*. The write happened on a person's click, by the person with the right role, through the approved agent, and the audit trail names both.
+

== Show: on the platform

The governance beat for what the audience just watched: rebecca refused, marcus approving. Three screens, the same names.

. Select the *Keycloak* tab. In realm `parasol`, open *Events*, tab *User events*, and search for event type `TOKEN_EXCHANGE`. Expand the newest rows.
+
What you should see: one row per chat turn, client `parasol-claims-agent`, with the details `username` `rebecca` (and, after the approval, `marcus`), `subject_token_client_id` `parasol-portal` (the login it acted on) and `client_assertion_sub` `system:serviceaccount:parasol-secured:claims-agent` (the agent's own workload identity, no secret). Every tool call in this scenario was made by this agent on behalf of that person.
+
Then open *Clients*, `parasol-claims-agent`, tab *Client scopes*, `parasol-claims-agent-dedicated`, tab *Scope*.
+
What you should see: *Full scope allowed* off, and the agent's ceiling: the `tool:*` roles of `parasol-secured/claims-db`, `parasol-secured/policy-docs` and `parasol-secured/fraud-check` it may ever carry. A token the agent obtains holds only the roles that are in this ceiling *and* the person's own, which is why rebecca's token has no `tool:approve_payout` and marcus's does.
+
// SCREENSHOT: s1-keycloak-token-exchange.png — Keycloak admin, realm parasol, Events > User events filtered on TOKEN_EXCHANGE, one row expanded: client parasol-claims-agent, username rebecca, subject_token_client_id parasol-portal, client_assertion_sub system:serviceaccount:parasol-secured:claims-agent (Keycloak admin sign-in)
// SCREENSHOT: s1-keycloak-agent-ceiling.png — Keycloak admin, Clients > parasol-claims-agent > Client scopes > parasol-claims-agent-dedicated > Scope: Full scope allowed off and the assigned tool:* roles (Keycloak admin sign-in)

. Force the refused call past the agent. In the *Terminal* tab:
+
[source,bash,role=execute]
----
scripts/abuse.sh secured rebecca 1
----
+
What you should see:
+
* the headless agent, asked as rebecca, answers that it cannot approve: `approve_payout` is in no one's tool list, so the request goes nowhere;
* `forced at the MCP gateway, rebecca's own token: ... calls must come through an approved agent (got azp=parasol-demo-cli). (HTTP 403)`: a login token presented directly, without an agent, does not reach a tool (the scripts log in through the client `parasol-demo-cli`; the portal client is browser-only);
* `forced at the MCP gateway, rebecca via parasol-claims-agent: ... rebecca may not call approve_payout. (HTTP 403)`: through the approved agent, the gateway still checks the person's role on every tool call.
+
Select the *OpenShift Console* tab, *Observe*, *Dashboards*, project `openshift-operators`, dashboard *Parasol Assistant Token Spend*, row *Gateway decisions*.
+
What you should see: in *Gateway rejections by reason*, `403 not via an approved agent (MCP gateway)` and `403 role does not allow the tool (MCP gateway)` each counting up; *Tool calls by tool, user, agent and status* lists `approve_payout`, `marcus`, `parasol-claims-agent`, `200`. The panel note gives the Authorino log lines that name the person: `not via an approved agent: rebecca azp=parasol-demo-cli` and `tool approve_payout denied for rebecca azp=parasol-claims-agent`.
+
// SCREENSHOT: s1-dashboard-rejections.png — Console, Observe > Dashboards, openshift-operators, Parasol Assistant Token Spend, row "Gateway decisions": the rejections table with both 403 reasons and the tool-calls table with approve_payout / marcus / parasol-claims-agent / 200 (OpenShift admin sign-in, after abuse.sh secured rebecca 1 and marcus's Approve)

. Back in the *Portal secured* tab (as marcus), click the `trace <id>` link under the approved card.
+
What you should see: the *MLflow* trace of the approval, in workspace `parasol-secured`: user `marcus`, tags `agent` `parasol-claims-agent` and `action` `approve_payout CLM-1001`, and a `gateway.authz` span with status OK. Together with the timeline line "Approved by marcus via parasol-claims-agent", the payout is on record as *agent X on behalf of user Y*, in the identity provider, at the gateway and in the trace.
+
